## G19 (docs/04 §11)
- `efn_online_quote(..., promo_codes)` selalu dikirim (`[]` bila kosong); `efn_online_place(order: { ..., promo_codes })`. Hasil quote: `promo_applied`/`promo_rejected` (dinormalisasi huruf besar, ⊆ permintaan, tidak beririsan) dan baris `reward: true` (nominal ≤ 0; baris non-reward tetap ≥ 0). Field tambahan Odoo (mis. `reward_id`) tidak diteruskan.
- Blok `channel` katalog + `brand_code` (§11.3). API key per kanal: `ODOO_API_KEY_ONLINE_<KODE>_FILE` / secret `odoo_api_key_online_<kode>` (G20: `gl`, `pb`, `bcr`, `bcf`; kode berhifen tetap didukung format `-`→`_`); nama env/path hanya diturunkan dari kode yang lolos regex §10.2 (tanpa traversal).
- SEC-133: pemeriksaan start "env literal" di luar `APP_ENV=dev` hanya menolak `ODOO_API_KEY_ONLINE_<KANAL>` bernilai; `…_FILE` (path secret, selalu di-set compose) tidak ditolak.
- Issue quote: `PRODUCT_ISSUE_CODES` = `out_of_stock`, `qty_limit` (SEC-131, qty > batas per baris kanal) — wajib `product_id`; kode lain `^[a-z_]{1,40}$` (mis. `order_limit`, boleh `product_id: null`) tetap diteruskan. Tagihan < Rp1 hanya sah bila ada issue (L-35). Stub: `maxQtyPerLine` default 20 → issue `qty_limit`; place ber-`qty_limit` → `invalid_input` (asumsi); stub tidak pernah mengembalikan `amount_payable` < 1 tanpa issue.

## G20 (docs/04 §12.2–§12.3)
- `efn_online_place(order: { …, payment_mode: "counter", counter_code: "<8 karakter>" })` — kedua field **hanya** dikirim untuk bayar di kasir (payload QRIS & `payload_sha256` Odoo tidak berubah). L-56: `counter_code` dibuat BFF (pola `pickup_code`), Odoo hanya menyimpan hash dan **tidak** mengembalikannya; field `counter_code` di respons place diabaikan parser. Stub: counter tanpa kode / qris dengan kode → `invalid_input`; `payAtCounter(ref, code?)` mencocokkan hash.
- Blok `channel`: `payment_modes` = **array string** (L-57; string/bentuk lain → `invalid_response`; mode di luar `qris|counter` dibuang; tidak ada → `null` → BFF memakai `ONLINE_PAYMENT_METHODS`).
- Event `review` dapat membawa `review_reason` (`counter_paid_after_cancel|counter_paid_after_expiry` dipakai; nilai lain diabaikan → null), ikut sidik event bila ada.
- Order counter: BFF tidak memanggil `efn_online_mark_paid` / `efn_online_refund_settled` (Odoo `invalid_state`, L-57). Event baru `refund_settled` (L-58) diterima di `POST /v1/pos/online/order-events`.
- L-60 (SEC-145): `efn_online_counter_refund_authorize(channel_code, platform_order_ref, authorization: { idempotency_key, refund_id, refund_ref|null, amount })` — pool saga, key kanal. Respons `{ authorized?: boolean, state?: string }` (absen = true). **Asumsi**: nama argumen ke-3 `authorization` dan bentuk respons belum dikonfirmasi builder Odoo. Stub: idempoten per key (payload beda → `idempotency_conflict`), SO non-counter/belum lunas → `invalid_state`, nominal > tagihan → `amount_mismatch`.
- Katalog item: `weight_kg` (nullable; negatif/bukan angka → `invalid_response`).
- Issue quote: `weight_missing` (wajib `product_id`, masuk `PRODUCT_ISSUE_CODES`) dan `weight_limit` (wajib `product_id: null`, `ORDER_ISSUE_CODES`); allowlist `KNOWN_ISSUE_CODES` = out_of_stock, qty_limit, order_limit, weight_limit, weight_missing.
- Event `paid` dapat membawa `payment: { method: "counter"|"qris" }` (field lain diabaikan, tanpa identitas kasir; metode lain → 400).
- **Asumsi terhadap Odoo** (perlu dikonfirmasi builder E-45): (1) L-56: Odoo menerima `order.counter_code` (masuk `payload_sha256` sebagai bagian payload → replay idempoten dengan kode yang sama dari BFF), menyimpan hash, dan lookup POS mencocokkan hash; (2) mode tidak diizinkan kanal → `UserError efn_online:invalid_input` (BFF memetakan 503 + alert; BFF memeriksa `payment_modes` lebih dulu); (3) `efn_online_mark_paid` jalur BFF ditolak untuk SO counter; (4) `efn_online_status` melaporkan `confirmed|stock_short|review` setelah pelunasan POS; (5) L-58: refund order counter selesai dilaporkan lewat event baru `refund_settled` `{ refund: { refund_ref, amount, settled_at, provider_refund_ref: "pos:<uuid>" } }` (`refund_ref` = ref dokumen `efn_online_refund`, `amount` = nominal refund persis); `refunded` hanya berarti refund diminta; (6) setelah `efn_online_cancel`, lookup kode bayar di POS ditolak.

Risiko: R-T10 (saga), R-S03 (Odoo publik — dicegah), R-T15 (API key kedaluwarsa → `efn_online_odoo_auth_failures_total`).
