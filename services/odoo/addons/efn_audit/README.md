# efn_audit

Log audit nilai lama/baru per aturan model untuk Odoo CE 19 — pengganti OCA `auditlog` + `efn_setup_audit/patches.py` (Gelombang 10). Implementasi sendiri, **LGPL-3**, `depends: base, efn_core`.

- **Spesifikasi:** `docs/08_ODOO_FIT_GAP.md` §5.1 (F-17). **ADR:** ADR-031 (tanpa dependency modul pihak ketiga), ADR-020 (poin member di BFF, bukan Odoo).
- **Risiko dimitigasi:** R-S10 (insider mengubah harga/stok/parameter), R-B06 (fraud promo kasir), SEC-07 (perubahan HP member), bug OCA auditlog × ORM 19 (`ThrowAwayCache` → `AssertionError: Could not find all values … to flush them` saat membuat produk). **UU PDP:** HP/email disimpan ter-mask; log partner dihapus saat erasure (`efn_privacy`).
- **Aturan per model** ada di `efn_setup_audit` (data-only: harga, pricelist, promo loyalty, opname stok, kontak, parameter `efn.*`). Modul ini tidak bergantung `product`/`stock`/`loyalty`.

## Model
| Model | Isi | Catatan |
|---|---|---|
| `efn.audit.rule` | `name`, `model_id` (unik), `model_name`, `active`, `log_create/write/unlink`, `tracked_field_ids` (kosong = semua field memenuhi syarat), `excluded_field_ids`, `masked_field_ids`, `filter_domain`, `capture_unlink_values`, `retention_days` | Constraint: bukan `efn.audit.*`/transient/abstrak; field milik model; domain divalidasi (`safe_eval` + `_search`). Tanpa `company_id` (aturan per model untuk seluruh DB — pengecualian konvensi, sengaja) |
| `efn.audit.log` | `user_id` (uid asli walau `sudo()`), `origin_user_id` (uid pemicu bila `with_user(SUPERUSER_ID)`, SEC-46), `is_sudo`, `operation` (`create/write/unlink/purge`), `model_id`, `model_name`, `res_id`, `res_name`, `company_id` (company record sesudah write / sebelum delete), `rule_id`, `line_ids`, `note` (purge) | Index `(model_name, res_id)` |
| `efn.audit.log.line` | `field_id`, `field_name`, `field_label`, `old_value`, `new_value`, `old_ref`/`new_ref` (`model,id[,id…]` untuk M2o/M2m), `is_masked`, `company_id` (related stored dari log) | |

"Field memenuhi syarat" = stored, bukan `one2many`/`binary`, bukan `id/display_name/create_*/write_*`, bukan `message_*`/`website_message_ids` dan bukan field `mail.activity.mixin` (`activity_ids`, `activity_state`, … dikecualikan per **nama**, bukan prefix, agar field bisnis seperti `activity_epoch` tetap teraudit — L-81).
**Denylist global** (tidak pernah dicatat walau dipilih): nama mengandung `password`, `secret`, `token`, `api_key`, `totp`, `signature`; semua field `binary`; `res.partner.efn_member_hash`.
**Denylist tambahan (Gelombang 13):** `res.users.apikeys.key`/`index` (hash & 8 karakter awal API key).
**Format nilai:** M2o → nama (+ ref), M2m → nama dipisah koma (maks 20) + ref id; **pada write, x2many disimpan sebagai selisih** (`old_value` = `dihapus: …`, `new_value` = `ditambah: …`; `old_ref`/`new_ref` = daftar id lengkap sebelum/sesudah). Relasi ke **model orang** (`res.partner`, `res.users`, `res.partner.bank`, `hr.employee`) = `model,id` tanpa nama (SEC-56); relasi ke `res.groups` = **xmlid** (mis. `base.group_system`; tanpa xmlid → `res.groups,id`). Selection → label, float → presisi field (bila ada `digits`), monetary → `repr`, date/datetime → ISO, html → teks polos, semua dipotong 2000 karakter.
**Masking** (sebelum masuk DB; nilai lengkap tidak pernah disimpan). Dua sumber, digabung: (a) `masked_field_ids` aturan; (b) **wajib di kode** (Gelombang 11, SEC-45, `models/audit_policy.py`) — field char/text yang namanya mengandung `phone`, `mobile`, `email`, `npwp`, `ktp`, `passport`, `identification`, `acc_number`, atau bertoken `vat`/`nik`/`nib`/`ssnid`/`sinid`/`nitku`/`street`/`street2`/`street3`/`zip`/`address`/`login` (Gelombang 13, SEC-56), serta field date/datetime/char yang namanya mengandung `birth` (→ `****-**-**`), walau tidak dipilih di aturan; `city`/`state`/`country` sengaja tidak (granularitas rendah); `login` → email `a***@domain`, HP `62812****890`, lainnya `****(panjang)`; nama orang (`res.partner.name/complete_name` bukan perusahaan, `res.users.name`, `hr.employee.name`) → inisial `B*** S***`. Format: HP → `mask_phone` efn_core setelah normalisasi `62…` (`62812****890`); email → `a***@domain`; NPWP/NIK/rekening → `****` + 3 digit terakhir bila ≥ 10 digit, selain itu `****(panjang)`; lainnya → `****(panjang)`. `res_name` model orang (`res.partner`, `res.users`, `res.partner.bank`, `hr.employee`) = `model,id` (tanpa nama).

## Mekanisme hook (`models/base.py`)
Override `create`/`write`/`unlink` di `_inherit = "base"` (pola resmi Odoo, tanpa monkeypatch registry). Hook berada di dasar MRO sehingga melihat `vals` final setelah override modul lain (mis. kunci HP `efn_pos_otp_gate`) dan tidak perlu restart setelah install/upgrade.

Alur `write`: aturan dari `ormcache` (namedtuple + frozenset, bukan recordset) → keluar cepat bila tidak ada aturan / registry belum siap (install/upgrade) / transient/abstrak / model log → **irisan field dilacak ∩ vals sebelum membaca apa pun** (kosong → langsung `super`; contoh `stock.quant.write({'quantity': …})` di setiap mutasi stok) → `filtered_domain` → `read(load=False)` lama → `super().write` → `read` baru → hanya field berubah → satu `create` batch log + baris (sudo). `create` mencatat hanya field dilacak yang ada di `vals`; `unlink` menulis header (+ snapshot bila `capture_unlink_values`). Tidak ada `ThrowAwayCache`, penukaran cache, `invalidate_all`, atau SQL ke tabel model yang diaudit. Kegagalan menulis log **tidak ditelan** (transaksi gagal).
`efn.audit.rule` sendiri **selalu** diaudit (hard-coded). Cache aturan dibersihkan pada create/write/unlink aturan (`registry.clear_cache()` — disinyalkan ke worker lain), jadi aturan baru langsung aktif.

## Keamanan
- Grup (kategori *EFN Audit*): **Auditor** (`efn_audit.group_auditor`, baca log), **Auditor Data Pribadi Lintas PT** (`efn_audit.group_auditor_personal`, implies Auditor; tidak diberikan ke siapa pun secara default — penunjukan auditor holding/DPO = keputusan klien) dan **Manager** (`efn_audit.group_manager`, implies Auditor, kelola aturan). `base.group_system` → Manager (bukan auditor data pribadi).
- ACL: aturan — auditor `r`, manager `rwcu`; log & baris — auditor `r` saja. Tidak ada grup dengan create/write/unlink log.
- **Immutable terhadap ORM/RPC:** `write`/`unlink` log & baris → `UserError` selalu (termasuk admin dan `sudo()`), kecuali di dalam metode privat `_efn_audit_purge_*` yang memasang penanda di `cr.cache` (bukan context — context bisa diisi klien RPC). **Admin sistem tetap dapat memengaruhi log** lewat kode server action/cron (memanggil metode privat atau SQL), uninstall modul, atau akses DB — dimitigasi oleh butir tamper resistance di bawah, bukan dicegah.
- Record rule (Gelombang 11, SEC-45/46; `security/efn_audit_security.xml`, noupdate=0): **Auditor** → log `company_id` ATAU `prev_company_id` (company sebelum record dipindah) ∈ company yang diizinkan, plus log tanpa company yang **bukan** data pribadi (`is_personal = False`: parameter, aturan audit, server action, cron, modul). **Auditor Data Pribadi Lintas PT** → tambahan semua log tanpa company (termasuk kontak pelanggan, yang umumnya tanpa company). `is_personal` = log model orang atau memuat baris ter-mask (compute stored; dihitung ulang untuk log lama saat upgrade). Rule lama dihapus migrasi `19.0.1.1.0/post-migrate.py`.
- **Hak akses = model kontrol (Gelombang 13, SEC-49):** `res.users` (`group_ids`, `active`, `login`, `company_ids`, `company_id`, `share`), `res.groups` (semua field: `user_ids`, `implied_ids`, `implied_by_ids`, `rule_groups`, `menu_access`, `name`, …), `ir.rule` dan `ir.model.access` (semua field), `res.users.apikeys` (create lewat override `_generate` — Odoo menulisnya dengan SQL — dan unlink; `name`, `user_id`, `scope`, `expiration_date`, tanpa key). Relasi grup–user diaudit dari **dua sisi** (Settings → Users maupun form grup). Saat create model kontrol, semua field dilacak yang bernilai ikut dicatat (grup default user baru terlihat). Log `res.users` ber-`company_id` user (auditor PT melihat perubahan user PT-nya; `is_personal`); log grup/rule/ACL tanpa company dan bukan data pribadi (uid, bukan nama). Log ini tidak ikut GC dan `_efn_audit_purge_records` menolaknya. Nama field diverifikasi di image `odoo:19.0` yang dipin (`res_users.py:257`, `res_groups.py:17,69,74`, `ir_rule.py:22-30`, `ir_model.py:2086-2093`, `res_users.py:1519-1529,1591-1613`).
- **Tamper resistance (Gelombang 11, SEC-43):** (1) retensi minimum hard-coded `MIN_RETENTION_DAYS = 365` — parameter `efn.audit.retention_days` dan `retention_days` aturan di bawahnya (selain 0 = selamanya) atau bukan bilangan bulat **ditolak** dengan pesan jelas; nilai kecil yang lolos lewat SQL diperlakukan sebagai minimum oleh GC; (2) log operasi `purge` dan log **model kontrol** (`efn.audit.rule`, `ir.config_parameter`, `ir.actions.server`, `ir.cron`, `ir.module.module`, `base.automation`) **tidak pernah** dihapus GC, dan `_efn_audit_purge_records` menolak model kontrol; (3) model kontrol **selalu diaudit** dengan spesifikasi bawaan (`CONTROL_SPECS`: parameter `efn.audit.*` key/value; server action semua field termasuk `code`; cron jadwal/user/aktif tanpa `nextcall/lastcall`; modul `state`; otomasi) walau aturannya diarsipkan/dihapus — aturan admin untuk model yang sama hanya **menambah** (field gabungan, filter OR, flag dipaksa aktif); (4) aturan bawaan (punya xmlid, mis. dari `efn_setup_audit`) tidak bisa dihapus, hanya diarsipkan (tercatat) — kecuali uninstall modul pemiliknya; (5) **sink eksternal**: setiap log model kontrol + log purge dikirim **setelah commit** ke logger `odoo.addons.efn_audit.sink` (`EFN_AUDIT_SINK {json}`: id log, operasi, model, res_id, uid, sudo, nama field, catatan purge — tanpa nilai/PII) → Promtail → Loki, di luar kendali admin Odoo.
- **Format sink v2 (Gelombang 13, SEC-49/51):** satu baris `EFN_AUDIT_SINK {json}`; JSON `ensure_ascii` + kunci terurut sehingga newline/karakter kontrol/Unicode di nilai (mis. `note`) selalu di-escape — teks pengguna tidak bisa memecah baris atau membentuk event kedua. Kunci: `v` (=2), `audit_op`, `critical`, `log_id`, `operation`, `model`, `res_id`, `uid`, `origin_uid`, `sudo`, `fields`, `note`, `mac`, dan untuk hak akses `groups_added`/`groups_removed` (xmlid), `users_added`/`users_removed` (uid), `key_owner_uid`. `audit_op`: `access_grant`, `access_revoke`, `access_rule_change` (ir.rule/ACL, selalu `critical`), `apikey_create`, `apikey_revoke`, `user_change`, `group_change`, `control_change` (model kontrol lain), `purge`, `purge_manual` (critical). `critical` = grant yang (langsung/implied) mencakup `base.group_system`, `base.group_erp_manager`, `efn_audit.group_auditor_personal`, `efn_audit.group_manager`. `mac` = HMAC-SHA256 hex atas `sink_canonical(event)` (JSON tanpa `mac`, `sort_keys`, separator `,`/`:`, ASCII) dengan kunci dari file `EFN_AUDIT_SINK_KEY_FILE` (default `/run/secrets/efn_audit_sink_key`, ≥ 32 byte) — dibaca proses Odoo saja, tidak ada di DB/`ir.config_parameter`, tidak terjangkau server action (`safe_eval` tanpa `open`/modul). Kunci tidak ada → `"mac": null` + WARNING sekali per proses (bukan diam-diam). Verifikasi di luar Odoo (ETL/rekonsiliasi: `hmac.compare_digest(mac, sink_mac(key, json.loads(line)))`). HMAC membuktikan baris berasal dari proses Odoo, **bukan** bahwa isinya benar: admin yang menjalankan kode server action tetap dapat memanggil hook dan menghasilkan baris bertanda tangan atas namanya sendiri (uid tercatat).
- **Purge (Gelombang 13, SEC-51 butir 4):** `_efn_audit_purge_logs` menolak log yang belum melewati retensi efektifnya (per aturan / global, minimum 365; 0 = selamanya → tidak ada yang dihapus). Log purge di luar jalur resmi (GC retensi / erasure — penanda `cr.cache`) diberi awalan `manual:` dan `audit_op=purge_manual` sehingga tidak lolos pengecualian alert `retensi:`/`erasure:`. Penanda dapat ditiru kode admin — menaikkan biaya, bukan mencegah. Aturan alert Loki/Alertmanager dan ETL `efn_audit_log` → ClickHouse (user tanpa DELETE, hash berantai) = tugas devsecops/data (spesifikasi di laporan Gelombang 11).
- **Gelombang 15 (r8):** (SEC-78) catatan purge (`note`, teks bebas pemanggil/admin) di-mask **di sumber** sebelum disimpan, di-MAC, dan dikirim ke sink — HP Indonesia dengan/tanpa pemisah (`0812-3456-7890`, `+62 812 …`, `(+62) 812…`, `628…`) → `62812****890`, email → `b***@domain`, NIK/NPWP 15–16 digit & NPWP berformat → `****123` (`audit_policy.mask_free_text`); tanggal/jam/angka pendek tidak tersentuh. (SEC-75) `efn.pos.self_order_mobile_allowed` (sakelar QR-order ponsel `efn_setup_pos`) masuk `CONTROL_SPECS` `ir.config_parameter` → selalu diaudit, log tidak ikut GC. Belum: rule deteksi Loki `{stream="efn_audit_sink"} |~ "(\+?62|0)8[1-9][0-9]{7,11}"` (devsecops).
- Batas: superuser PostgreSQL / admin sistem yang menjalankan SQL dari server action tetap bisa menghapus baris (mitigasi = least privilege DB docs/04 §7.3, `base.group_system` hanya Superadmin, sink Loki di atas). Uninstall `efn_audit` men-drop tabel (jejak tersisa: log `ir.module.module` di sink). Hash berantai per baris belum dibuat (fase 1).
- `user_id` `ondelete="restrict"`: user yang punya log tidak bisa dihapus (arsipkan saja) — jejak tidak boleh hilang.

## Retensi & erasure
- `@api.autovacuum _gc_efn_audit_logs` (cron *Base: Auto-vacuum internal data*, harian): hari = `rule.retention_days` (>0) atau `ir.config_parameter` `efn.audit.retention_days` (tidak valid/hilang → 730; `0` = simpan selamanya), keduanya minimal 365 (SEC-43). Log `purge` dan log model kontrol tidak pernah dihapus. Maks 10.000 log per jalan; satu log `purge` dengan `note="retensi: n log"` (ikut dikirim ke sink).
- Erasure UU PDP: `env["efn.audit.log"]._efn_audit_purge_records(model_name, res_ids)` → hapus log record tsb, kosongkan `old/new_value` + `old/new_ref` di baris log model lain yang menunjuk record tsb, tulis satu log `purge` tanpa id/nama. Dipakai `efn_privacy`.

## Tampilan
Menu atas **Audit** (grup Auditor): *Log* (list/form + baris; search model/record/user/operasi/company/field; filter *Hari ini*, *7 hari* (default), *Harga*, *Promo*, *Pelanggan*, per operasi; group by model/user/tanggal) dan *Aturan* (grup Manager).

## Cara uji manual
1. `odoo -d <db> -i efn_setup_audit` (menarik `efn_audit`).
2. Ubah harga jual produk → *Audit → Log*: operasi Write, baris `list_price` lama/baru.
3. Ubah HP kontak → baris `phone` ter-mask (`62812****890`), *Disamarkan* tercentang.
4. Coba hapus log dari UI/RPC sebagai admin → ditolak.
5. Ubah parameter `efn.pos.otp_required_for_promo` → tercatat; parameter non-`efn.*` tidak.

## Batasan / belum terverifikasi
- Overhead diukur di test (container CI lokal): import 200 `product.template` dengan aturan semua field ≈ +22 query (+5%), waktu ±1,2 s vs 0,8 s (satu run, belum PoC beban 100 order POS / 1.000 produk di staging). Bila mahal: persempit `tracked_field_ids` produk ke harga/pajak/kategori/aktif.
- Penulisan selama install/upgrade modul (`registry.ready = False`) tidak dicatat (by design, seperti data XML). Juga tidak tercatat: `_write`/SQL langsung — SEC-46.
- SEC-46 (Gelombang 12): `with_user(SUPERUSER_ID)` tetap tercatat `user_id` = OdooBot, tetapi `origin_user_id` (User Pemicu) diisi dari sumber tepercaya: `request.session.uid` (sesi HTTP) atau helper `elevate_as_superuser(env)` (penanda di `cr.cache`, tidak bisa diisi lewat context RPC). Cron/consumer tanpa sesi HTTP yang memakai `with_user(SUPERUSER_ID)` langsung (bukan helper) tetap kehilangan uid pemicu — kode kustom wajib memakai helper. Sink Loki memuat `origin_uid`.
- Index purge erasure (Gelombang 12): btree parsial `text_pattern_ops` pada `old_ref`/`new_ref` (`WHERE ... IS NOT NULL`) untuk `=like "model,%"`; pemakaian index diverifikasi EXPLAIN di test (seqscan dimatikan), belum diukur pada volume besar. Upgrade `19.0.1.1.0 -> 19.0.1.2.0` (kolom + 2 index baru) dibuat otomatis ORM; belum diuji pada DB dev/staging.
- Sink Loki hanya untuk log model kontrol + purge (bukan semua log), retensi Loki 30 hari; salinan jangka panjang = ETL ClickHouse (belum dibuat). Baris sink dari transaksi yang gagal commit tidak dikirim (by design).
- Hak akses (Gelombang 13): tidak tercatat — perubahan saat install/upgrade modul (registry belum siap: data XML/CSV ACL, rule, grup), penghapusan API key kedaluwarsa oleh autovacuum Odoo (SQL `DELETE`), perubahan lewat SQL langsung / `odoo shell` di luar ORM. Implikasi grup tidak di-expand ke daftar user (sink memuat grup yang di-imply + `critical`). Alert Loki untuk `audit_op`/`critical`, verifikasi HMAC di ETL, dan mount secret `efn_audit_sink_key` = tugas devsecops/data (laporan Gelombang 13); sampai itu `mac` null di dev/CI.
- Migrasi `19.0.1.1.0` diuji di harness (install HEAD 19.0.1.0.0 → `-u efn_audit,efn_setup_audit`): rule lama terhapus, 4 rule baru, `is_personal` log partner lama = True, 0 ERROR. Belum diuji pada volume dev/staging.
